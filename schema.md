# WiseQ stock analytics - data model

Run date: **2026-11-24**. Generated by `wiseq_stock.analytics`.

## Tables and grain

| Table | One row is | Rows |
| --- | --- | ---: |
| `dim_product` | one product | 246 |
| `dim_date` | one date | 1 |
| `dim_supplier` | one supplier | 24 |
| `fact_stock_position` | one product per run | 246 |
| `fact_reconciliation` | one product per run | 0 |
| `fact_exception` | one product per run per section | 249 |
| `measure_catalog` | one measure | 12 |

## Relationships

```
fact_stock_position[product_id]  --> dim_product[product_id]
fact_stock_position[run_date]    --> dim_date[date]
fact_reconciliation[product_id] --> dim_product[product_id]
fact_exception[product_id]      --> dim_product[product_id]
dim_product[supplier_id]         --> dim_supplier[supplier_id]   (single direction)
```

## Loading it in Power BI

1. **Get Data → Text/CSV** on the folder `analytics/`, or
2. **Get Data → SQLite** on `analytics/wiseq_stock.sqlite` (ODBC driver), or
3. **Get Data → Folder** on the CSV folder and pick `dim_product` as the
   dimension and `fact_stock_position` as the fact table.

Then create the measures: open `measure_catalog.csv`, copy the `dax` column
into a new measure with the same name. Every measure is defined once, there.

## Notes that matter for the numbers

- `stock_derived = TRUE` marks a bundle whose stock was computed from its
  parts. It is the **same physical stock** as the parts, so it must never be
  added to the physical stock measure.
- `to_order_units` and `order_value_eur` are a **proposal**. Nothing is
  ordered by this model; a human approves every line.
- A blank `days_of_stock` or `cover_months` means **unknown**, not zero.

python -m wiseq_stock --workbook source-data/... --ledger source-data/... \
